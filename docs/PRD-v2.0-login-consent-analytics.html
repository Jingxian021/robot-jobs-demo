Modification PRD / Technical-agnostic

把“可浏览的招聘站”变成
“可度量、可持续优化的产品”

本次修改在现有 Robot Works demo 上增加四件事：邮箱登录、分辖区的 Cookie 同意、带收藏能力的个人设置页， 以及一个只对内部开放的产品优化看板。核心目的不是增加功能数量，而是让团队第一次能看到 “哪个市场、哪类筛选、哪种对比行为最终带来了外部申请”。

评审摘要 — 先看这五条

  1. 存在一个硬阻塞：当前站点托管在 GitHub Pages，是纯静态页面。邮箱登录、服务端事件采集、后台看板都无法在纯静态托管上真实运行。需要先确认服务端/托管方案，否则本期只能交付“假数据可点击原型”，不能上线收集真实邮箱。
  2. v1 的表述只适用于 v1：“不收集个人数据”“无账户”是 v1 的范围声明，不是永久承诺。v2 是后续版本，新增邮箱账户与体验分析；需要更新对外说明，但仍不收集简历、不做站内申请、不用于广告或对外销售。
  3. 关键判断：登录保持可选。访客仍可筛选、收藏（本机）、对比、跳转申请。登录只用于跨设备同步、个人设置、数据导出/删除。这样不破坏 v1 的“零摩擦退出”。
  4. 关键判断：语言不等于司法辖区。EN / JA / ZH / DE 是界面语言，不是法律辖区。Cookie 规则必须按 IP 识别到的国家决定，语言只决定“用哪种语言展示规则”。EN 是国际英语默认，不因为选了英文就默认追踪；美国按 IP 单独识别。无法识别时，默认采用最严格的“先同意后追踪”。
  5. 关键判断：后台默认只看伪匿名聚合数据。管理员默认看到的是聚合指标和 UUID，不是用户邮箱。只有 Owner 角色可在填写理由后被审计地查看邮箱，避免“监控”变成无边界的窥探。

01背景与目标

v1 已经能让人完成“筛选 → 看详情 → 去公司官网申请”。但它是纯静态站点：收藏和对比只存在于当前浏览器， 换设备就丢失；团队也无法知道哪些筛选、哪些职位、哪次对比真正带来了申请。 换句话说，v1 能回答“页面长什么样”，不能回答“用户为什么回来、哪里值得继续投入”。

v2 的产品回应是增加一层最小可用的账户与度量基础设施，而不是把招聘站改造成社区或申请系统。 可观察的完成状态有三个：

  • 同一个用户在设备 A 收藏职位与公司后，能在设备 B 登录并看到同样的收藏。
  • 任一目标市场的用户，在非必要追踪启动前，能明确选择“全部接受 / 全部拒绝 / 自定义”，并能随时改回。
  • 内部运营者能回答：哪些筛选带来详情打开、对比会话有多少最终点了申请、不同辖区的同意选择如何分布——且默认看不到用户邮箱。

目标（以可观察行为表述）

ID目标完成证据
G1收藏可跨设备延续用户在新设备登录后，已收藏职位与公司数量与旧设备一致（除已失效职位）。
G2四个市场可合规进入四个辖区档案下，非必要 Cookie 的默认状态、按钮文案、重新征求时机均符合本文件规则；拒绝后站点功能不受损。
G3关键漏斗可度量后台可查看“筛选 → 详情 → 对比 → 外部申请”的分段转化，并显示同意覆盖率。
G4不破坏零摩擦浏览未登录用户仍可完成 v1 的全部核心动作；登录提示不遮挡内容、不重复弹出。
范围判断 本期不做“给用户看的个人数据仪表盘”，也不做雇主后台。后台是内部运营工具，不是产品对外功能。

02版本演进说明：v1 的边界只适用于 v1

v1 文档里的“不收集个人数据”“无账户、无登录”，描述的是 v1 的产品范围，不是对后续版本的永久承诺。 v2 是新的版本，新增了邮箱账户与体验分析，因此需要一套新的对外说明。 这里不是“修订 PII 边界”，而是明确 v1 与 v2 各自的范围。

v2 仍然保持的底线：不托管简历、不做站内申请、不做雇主账户、不把数据用于广告、营销或对外销售。

v1 的表述v2 的定位需要更新的位置
“does not collect personal data”（v1 范围） v2 仅在用户主动登录时收集邮箱；体验事件去标识化，不写入邮箱。仍不收集简历、申请材料、证件或支付信息。 首页 hero 文案、About、隐私政策、页脚
“No account, no sign-in, no profile.” v2 账户可选：浏览、本机收藏、对比、申请均无需登录；账户只用于跨设备收藏与设置。 Header、登录页、设置页
“Nothing personally identifiable.” 邮箱属于个人数据；体验事件使用随机 UUID 与会话 ID，看板默认只显示聚合与 UUID。 隐私政策、同意文案、看板权限
v1 将 accounts / saved-jobs sync 列为 Out of Scope v2 将其纳入范围，但仅限邮箱账户与收藏同步。 v1 第 11 节、路线图
对外表述 不要说“我们仍然不收集任何数据”。准确说法是：v1 不收集；v2 只在登录时收集邮箱，并在同意后收集用于改进产品的匿名行为事件。

本文件中所有涉及 GDPR、TTDSG、APPI、PIPL、CCPA/CPRA 的描述均为产品规则草案，不构成法律意见。 上线前必须由目标市场的法务或 DPO 逐条复核，尤其是同意记录保存期限、跨境传输、以及中国大陆的数据本地化要求。

06.1登录页（Land in）

FR-AUTH 目标：用最少的个人信息建立可跨设备延续的账户，同时不把未登录用户挡在内容之外。

入口

  • Header 右侧 “Sign in”（访客）或账户菜单（已登录）。
  • 设置页深链接：未登录访问 settings 时跳转登录页，并携带 next=settings。
  • 收藏后的非阻塞提示：“Saved on this device · Sign in to sync”。不自动弹窗，不遮挡列表。
  • 直接访问登录页 URL。

字段与校验

字段规则
邮箱必填；去除首尾空格并转小写；最大 254 字符；必须包含一个 @ 与有效域名结构；不允许换行。错误在字段下方就地提示，不使用仅颜色表达。
密码不存在。本期不做密码登录，也不做社交登录。
条款勾选不设“我已阅读”空勾选，避免虚假同意；在按钮下方以一行说明“继续即表示同意 Terms 与 Privacy Policy”，并提供可点击链接。
营销订阅本期不收集营销同意，不显示营销勾选框。

处理规则

  1. 提交后先做频率限制：同一邮箱 60 秒内不可重复发送；同一邮箱每小时上限 [TBD]；同一 IP 上限 [TBD]。
  2. 无论邮箱是否已注册，都显示同一句确认文案：“If an account exists for this address, we sent a one-time link.” 防止邮箱枚举。
  3. 首次使用某邮箱即创建账户；不区分“注册”和“登录”两个入口。
  4. 魔法链接 15 分钟内有效、只能使用一次、绑定邮箱；点击后建立会话并跳转。
  5. 链接过期或被使用过时，显示明确页面并提供“Send a new link”，不显示笼统错误。
  6. 跳转参数 next 只允许本站相对路径白名单；非法值一律回首页，防止开放重定向。
  7. 邮件只用于事务性通信（登录链接、账户删除确认）；不发送职位推荐或营销内容。

会话与退出

  • 会话默认 30 天 [TBD]，可在账户设置中“Sign out all devices”。
  • 退出后，本机收藏保留；账户收藏不再显示，直至再次登录。
  • 同一邮箱可在多设备同时登录；不限制设备数 [TBD]。

异常

  • 邮件进入垃圾箱：在 sent 状态提供 “Check spam” 与重发。
  • 用户关掉页面后再点链接：链接仍可用（未过期且未使用），成功后进入默认首页。
  • 用户在两个标签页同时点同一链接：第一个成功，第二个显示 link_used 并提示已登录。
  • 离线提交：阻止发送并提示检查网络。

06.2Cookie 与同意管理

FR-CONSENT 目标：按用户所在辖区决定“追踪是否需要先同意”，并让拒绝和接受一样容易。

关键修正 界面语言与法律辖区必须解耦。一个在德国用英文界面的用户，仍然适用欧盟的“先同意”规则； 一个在中国用中文界面的用户，不会因为语言是中文就自动适用美国规则。 正确顺序是：先按 IP 识别国家 → 映射辖区档案 → 再用当前界面语言展示文案。

识别与生效规则

  1. 首次访问时按 IP 识别国家，只保存国家代码，不保存完整 IP。
  2. 识别失败、匿名网络、或国家不在四个档案内时，使用“最严格档案”：默认不追踪，先征求同意。
  3. 用户可在“隐私设置”中声明自己所在辖区。生效档案取“识别结果”和“用户声明”中更严格的一个，防止通过切换地区降低保护。
  4. 用户旅行或更换网络后，在下次重新征求时重新评估；不会在页面加载中途悄悄切换规则。

分析门控

  • 在“先同意”档案下，同意前不加载分析脚本、不写分析标识、不发送事件。同意前发生的行为不补采。
  • 在“退出制”档案下，默认采集，但首层必须提供明确的退出入口；退出后立即停止。
  • 拒绝分析不影响筛选、收藏、对比、申请跳转与登录。
  • 后台每个指标旁必须显示同意覆盖率；覆盖率过低时，指标只能用于方向判断，不能当作全量事实。

异常与边界

  • IP 识别服务超时：直接使用 P0 兜底，不阻塞页面。
  • 用户禁用 JavaScript：只保留必要 Cookie，不展示分析；页面核心内容仍可读。
  • 政策文本加载失败：使用内置的当前版本文本，不允许回退到过期版本。
  • 用户在登录前后分别做出选择：以最新一次明确操作为准；登录不自动继承匿名同意，需在设置页确认一次 [需法务确认]。
  • 未成年人：产品不面向未满 16 岁用户 [需法务确认]。

  • 导出内容：账户基本信息（不含会话密钥）、收藏职位、收藏公司、同意记录历史。
  • 格式：JSON；小数据量立即下载，大数据量通过邮件发送一次性下载链接 [TBD]。
  • 导出不包含其他用户数据，不包含后台聚合数据。

  1. 入口仅在 Account 分区，使用文字按钮，不与“退出登录”并排，避免误触。
  2. 确认页说明：将删除账户、收藏与偏好；同意记录可能按法律要求保留为匿名证据；删除后不可恢复。
  3. 用户需输入邮箱或 “DELETE” 进行二次确认，并可选择填写原因（可选）。
  4. 确认后立即退出所有设备，账户进入 pending_deletion，30 天后彻底删除 [TBD，需法务确认]。
  5. 30 天内重新登录可取消删除；页面必须明确告知这一点。

  • 加载中：使用骨架屏，不显示空白页。
  • 网络失败：显示重试按钮，保留已加载内容，不清空列表。
  • 收藏列表为空：说明“尚未收藏职位”，提供 Browse jobs 按钮，不显示无意义的空表格。
  • 职位已下架：显示 Removed 状态与说明，不给出失效的 Apply 按钮。
  • 会话过期：提示重新登录，登录后回到原分区。

FR-SAVE 目标：保留 v1 “无需登录即可收藏”的低摩擦，同时让登录用户获得跨设备连续性。

首次登录的合并规则

  1. 登录成功后，如果本机存在收藏，显示非阻塞确认：“This device has 3 saved jobs and 1 company. Sync to your account?”
  2. 选择“同步全部”：取本机与账户的并集，按职位 ID / 公司 ID 去重；同一对象保留较早的收藏时间。
  3. 选择“暂不”：保留本机数据，不上传、不删除；下次登录再询问，不重复弹窗打断浏览。
  4. 同步失败：保留本机数据，提示重试；不允许出现“账户里有、界面上没有”的静默丢失。

同步与冲突

  • 同一账户在两台设备同时收藏同一职位：以先写入服务端的时间为准，不重复计数。
  • 设备 A 取消收藏、设备 B 同时收藏：以最后提交到服务端的操作为准；界面显示刷新后的真实状态。
  • 本期不要求实时推送；在下次打开页面或手动刷新后一致即可。
  • 离线时：允许本机继续收藏，但明确标记 “Will sync when online”；恢复网络后合并，冲突按上一条规则。

公司关注

  • 职位卡片与详情页增加 “Follow company”；已关注显示 “Following”。
  • 首页 Saved 视图增加 Jobs / Companies 两个标签；Companies 下列出已关注公司及当前开放职位数。
  • 本期关注公司不触发任何邮件或推送；设置页必须明确写出这一点，避免用户误以为会收到提醒。
  • 取消关注立即生效，不影响已收藏的该公司的职位。

职位失效

  • 职位过期后 7 天内仍可搜索，标记 “Closed”（沿用 v1）。
  • 收藏列表中 Closed 职位保留，Apply 按钮替换为 “View original posting”（若仍可访问）；否则只显示状态说明。
  • 职位从数据库移除：收藏项标记 Removed，保留 30 天 [TBD] 后自动清理，并给出一次安静提示。
  • 对比集中的职位被移除：只移除该项，其余保留（沿用 v1 6.3）。

分段与筛选

  • 时间范围：今天 / 近 7 天 / 近 30 天 / 近 90 天 / 自定义（导出上限 90 天）。
  • 必选分段：界面语言、辖区档案、登录状态、设备类型。
  • 可选分段：职位类别、公司、来源页面。
  • 所有数字旁显示统计口径提示与最后更新时间；数据延迟超过阈值时给出黄色提示 [TBD 阈值]。

隐私约束

  • 默认只看聚合与 UUID，不显示邮箱、不提供“按邮箱搜索用户”。
  • Owner 查看单个账户邮箱时必须：输入理由 → 二次确认 → 写入审计日志；单次展示，不支持批量导出。
  • CSV 导出只含聚合结果或脱敏 UUID，不含邮箱。
  • 后台自身也受同意约束：未同意分析的会话不出现在任何用户级视图，只计入“未同意”汇总。

状态与异常

  • 无数据：显示“该时间段没有满足条件的事件”，并给出清空筛选的按钮。
  • 权限不足：显示可申请的角色说明，不泄露任何数字。
  • 查询超时：显示重试，不展示部分错误数据。
  • 事件管道延迟：显示最后成功更新时间，不把旧数据伪装成实时。

身份与安全（产品层）

  • 魔法链接单次使用、15 分钟过期；重发有冷却与频率上限。
  • 导出与删除必须重新验证身份，防止会话被劫持后批量带走数据。
  • 后台敏感操作（查看邮箱、改角色）必须二次确认并留痕。
  • 不在分析属性、URL 参数、日志中写入邮箱或令牌。
  • 所有外部跳转使用新标签页，且不携带用户标识到雇主站点。

多语言与法律文本治理

  • 四个语言键集合必须完全一致；构建时检查缺键，缺键直接失败，不允许静默回退。
  • 法律文本（Privacy、Terms、Cookie 说明）按语言独立版本管理，版本号一致；不得用机器翻译直接上线。
  • 同意横幅上的文案与隐私政策中的类别定义必须逐字一致，避免“横幅说分析、政策说营销”的错位。
  • 时间、薪资、经验带沿用 v1 规范：币种 + 周期；经验写区间；日期按浏览器时区。

可访问性

  • 同意横幅、登录表单、设置页、后台均需键盘可达；焦点顺序合理，打开偏好中心时焦点进入，关闭后返回触发按钮。
  • 错误提示不能只靠颜色；对比度满足 WCAG 2.1 AA。
  • 动画可被“减少动态效果”系统设置关闭。

失败与恢复

  • 任何收藏/关注操作失败都要回滚界面状态并提示，不允许“看起来成功、实际没保存”。
  • 任何服务端错误都不应导致本机收藏被清空。
  • 登录邮件发送失败时，保留用户已输入的邮箱，提供重试。

08指标与决策方式

本次后台不是为了“看数字”，而是为了决定下一版改什么。因此只保留能触发动作的指标， 并强制按语言、辖区、登录状态分段。统一口径见 6.5 的 M1–M12。

领先指标与护栏

类型指标为什么看它
领先对比辅助申请率（M5）v1 的核心假设是“对比帮助决策”。如果对比会话并不带来更多申请，应优先改对比体验，而不是加更多职位。
领先登录转化率（M7）与魔法链接完成率（M8）区分“不想登录”和“收不到邮件/链接失效”，对应完全不同的改法。
护栏访客申请点击率（M6，未登录分段）登录功能不得降低未登录用户的申请意愿。
护栏同意拒绝率与同意覆盖率（M10）拒绝率异常高说明文案或默认值有问题；覆盖率过低说明后台数据不可当全量。
护栏过期举报率（M11）增长不能建立在过期职位上。

09依赖、风险与阻塞

ID风险 / 依赖影响处理建议
R1 静态托管无法承载账户与后台 阻塞上线；只能做假数据原型 先确定可运行服务端的托管与数据存储方案；PRD 确认后单独出技术方案。GitHub Pages 继续作为前端静态托管可以，但不能承担登录与事件写入。
R2 四市场法律复核未完成 可能导致同意流程、留存期限、跨境传输返工 上线前由法务/DPO 逐条确认；本文件所有法律描述都标记为草案。
R3 中国大陆数据本地化与跨境 可能需要独立部署与独立数据存储，成本与架构影响大 在 Q5 明确是否服务中国大陆用户；若服务，单独评估。
R4 魔法链接送达率 登录漏斗在第一步流失 配置 SPF/DKIM/DMARC；监控送达与点击；提供重发；不因送达问题改回密码登录。
R5 登录摩擦降低申请率 违背 v1 零摩擦原则 登录保持可选；所有提示非阻塞；用未登录分段的申请点击率做护栏。
R6 同意覆盖率低导致数据偏差 后台结论可能只代表愿意被追踪的用户 每个指标强制显示覆盖率；覆盖率低于阈值时只做定性判断 [TBD]。
R7 后台权限过宽 内部窥探风险，损害信任 默认聚合；邮箱查看需理由 + 审计；不提供批量导出邮箱。
R8 本机收藏合并失败导致数据“消失” 最严重的用户信任损失 并集合并、失败回滚、保留本机副本；合并前明确展示数量。
R9 四语法律文本不同步 某一语言版本承诺不一致，产生合规风险 版本号统一；缺键构建失败；法律文本人工审校。

ID问题为什么重要建议默认
Q1 本期是否保留邮箱登录？如果匿名采集已能拿到优化数据，是否先不做账户？ 登录不是采集数据的前提；它只解决跨设备收藏与账户设置。保留登录会增加工作量、PII 与合规成本。 先不做登录：匿名采集 + 本机收藏页 + 同意管理；若之后需要跨设备同步，再做可选登录。
Q2 若保留登录，是可选还是必须？ 决定是否破坏 v1 零摩擦浏览与申请路径 可选：访客可完成全部核心动作，登录只用于同步与设置
Q3 服务端与数据存储放在哪里？ 静态托管无法实现事件写入与看板；若不做登录，仍需要事件接收与存储 先确认可承载服务的托管方案，再进入开发；本期不锁定具体厂商
Q4 匿名会话是否要与登录用户关联？ 关联后可看单用户旅程，但隐私与合规成本更高 仅在登录后关联到随机 UUID；默认看板仍只显示聚合
Q5 是否服务中国大陆用户？数据是否必须本地化？ 影响部署、跨境传输与合规成本 先确认目标市场；若服务，单独做本地化评估
Q6 后台是否允许查看用户邮箱？ 涉及内部权限与隐私承诺 默认聚合 + UUID；Owner 理由化查看并审计
Q7 账户删除的宽限期与数据留存期限？ 影响用户预期与法律义务 删除宽限 30 天；事件 13 个月；同意记录撤回后 24 个月，均需法务确认
Q8 收藏公司是否要发新职位邮件？ 会引入营销同意与邮件基础设施，超出本期 本期不发；只做列表与筛选，设置页明确说明
